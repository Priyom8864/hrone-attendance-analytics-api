# REVIEW.md

I reviewed the starter against `openapi.yaml` and `DATA_MODEL.md`. The main problems I found are listed below. I have focused on defects that affect the contract, correctness, or behaviour under concurrent requests.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you'd fix it |
|---|---|---|---|---|
| 1 | `health()` | It always returns `{"status": "ok"}` and never checks MongoDB. | Stop MongoDB and call `GET /health`; it still reports success. | Run a MongoDB ping and return 503 if the ping fails. |
| 2 | `create_employee()` | The duplicate check and insert are separate operations, so two simultaneous requests can both pass the check. There is no unique-index setup in the starter. | Send parallel requests with the same `emp_code`; more than one request may succeed. | Create a unique index on `employees.emp_code` at startup and translate duplicate-key errors to 409. |
| 3 | `EmployeeIn` / `create_employee()` | The request model does not enforce the contract's date/time formats or require `shift_start` and `shift_end` to differ. `created_at` is also saved as a naive datetime and returned as a datetime rather than epoch milliseconds. | Try equal shift times or malformed `joined_on` / shift values; inspect the response's `created_at`. | Add request validation, store a UTC instant, and serialize instants as integer epoch milliseconds. |
| 4 | `compute_late_minutes()` | It builds the shift start by replacing the punch-in hour/minute, without first converting the instant to IST or handling the previous-day shift start for an overnight shift. | Test punches near the shift boundary with UTC/BSON datetimes or an overnight employee. | Convert instants to IST for calendar/time calculations and determine the correct shift start date before calculating lateness. |
| 5 | `compute_late_minutes()` | It does not truncate the punch instant to whole seconds before calculations. | Send a timestamp with milliseconds and check the stored value and late-minute result. | Truncate to whole seconds before computing and storing the instant. |
| 6 | `compute_work_hours()` | Python's built-in `round()` uses ties-to-even rounding, but the contract requires two-decimal half-up rounding. | Test a duration whose hour value is exactly halfway between two hundredths. | Use `Decimal` with `ROUND_HALF_UP` for the calculation and result. |
| 7 | `compute_overtime()` | The shift end is always built on the attendance date, so overnight shifts use the wrong end instant. It also returns any positive overtime instead of applying the 30-minute minimum. | Test a 22:00–06:00 shift, then test an out time 20 minutes after shift end. | Build the shift end on the correct date for overnight shifts and return overtime only when the floored duration is at least 30 minutes. |
| 8 | `create_employee()` | The duplicate check alone cannot guarantee uniqueness, and the code does not handle a MongoDB duplicate-key error. | A duplicate create may produce an unhandled server error instead of the required 409. | Rely on the unique index for the guarantee and catch `DuplicateKeyError` to return 409. |
| 9 | `list_employees()` | `skip = page * page_size` skips the first page instead of starting at `(page - 1) * page_size`. The query is not sorted by `emp_code`. | With `page=1`, the first page of employees is skipped; repeated calls may not have contract ordering. | Use `(page - 1) * page_size` and sort by `emp_code` ascending in MongoDB. |
| 10 | `list_employees()` | `total` counts all employees, even when a department filter is applied. Page and page-size bounds are not enforced. | Filter by a department and compare `total` with the number of matching employees; try invalid page values. | Count using the same filter as the item query and validate `page >= 1`, `1 <= page_size <= 100`. |
| 11 | `punch_in()` | It does not return 404 for an unknown `emp_code`; `emp` becomes `None` and later code can fail with a 500. It also accepts any status string rather than only `PRESENT`, `WFH`, or `ON_DUTY`. | Punch in for an unknown employee or send `status="ABSENT"`. | Check that the employee exists and validate the allowed punch-in statuses, returning the contract's status codes. |
| 12 | `punch_in()` | `datetime.fromtimestamp()` uses the machine's local timezone and creates a naive datetime. The `if body.punched_at` check also treats zero as if the timestamp were omitted. | Run with a non-IST machine timezone or send invalid timestamp values. | Validate epoch milliseconds strictly, convert from UTC, derive the attendance date in IST, and truncate to whole seconds. |
| 13 | `punch_in()` | The check-then-insert sequence is not safe for simultaneous punch-ins, and the starter creates no unique index on (`emp_code`, `date`). The response also adds an `id` field, which the contract says must not be returned. | Send two punch-ins for the same employee/date at once; inspect the response keys. | Add a unique compound index on `attendance_logs.emp_code` and `date`, handle duplicate-key errors as 409, and omit `_id`/`id` from API responses. |
| 14 | `list_attendance()` | It fetches every matching record into Python, sorts and paginates in memory. This will not scale to the specified 100,000 records. | Run it against a large collection and observe memory use and response time. | Apply filters, sort, `skip`, and `limit` in MongoDB; use a separate filtered count for `total`. |
| 15 | `list_attendance()` | The sort only uses `date` descending, but the contract also requires `emp_code` ascending for ties. It returns an `id` field and BSON datetimes are returned as datetime strings rather than epoch milliseconds. | Create records for multiple employees on the same date and inspect response ordering and timestamp fields. | Sort by `date` descending then `emp_code` ascending, and serialize attendance timestamps as epoch milliseconds without exposing an ID. |
| 16 | `list_attendance()` | It does not reject `date_from > date_to`, and the pagination parameters have no contract bounds. | Send a reversed date range or `page_size=101`. | Validate the date range and enforce the specified page/page-size limits. |
| 17 | Whole application / startup | No indexes are created at startup, and the required punch-out, regularization, analytics, and explain endpoints are missing. | Start the app and compare its routes and indexes with the contract. | Add idempotent startup index creation and implement the remaining endpoints according to `openapi.yaml`. |

## Looked at but not treated as a defect

- The collections use `emp_code` rather than MongoDB `_id` to identify employees. This is intentional in `DATA_MODEL.md`; API responses should not expose MongoDB IDs.
- A missing `history` field and a missing `half_day` field are valid legacy-data cases. The API should treat them as `[]` and `false`, respectively, rather than requiring a migration before it can read them.
- A weekday with no attendance document is not the same as an `ABSENT` record. Analytics must preserve that distinction.
